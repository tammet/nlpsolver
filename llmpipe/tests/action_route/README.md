## What belongs here

`tests/action_route/*.py` : the fixture tooling (`fixture_materialize.py`) and focused unit checks for `solver/lc_action.py`,
`solver/action_route.py`, `solver/action_replay.py`, `solver/action_gk.py`, `solver/action_answer.py` and
`solver/action_pipeline.py`. They run offline. They
make no provider request. A check that needs GK names the binary and its
SHA-256, and counts as a GK call in the package budget.

`tests/action_route/examples/` : formal-input examples of the action route
(`solve.py -actions -formal FILE`), generated from the reviewed gold by
`make_examples.py`. They are derived, not new gold; `make_examples.py --check`
and `check_action_route_e2e.py` find a drift from the gold.

`tests/action_route/gk_output/` : saved GK outputs, compressed copies of
archived launches, which `check_action_gk.py` reads as real output. They are
test input for the adapter's output reader, not gold. `SOURCES.sha256` names
the launch each one was copied from.

`tests/action_route/regression/` : saved model responses of earlier runs,
which five checks replay through the current controller
(`check_action_round2.py`, `check_action_round3.py`, `check_action_round4.py`,
`check_action_corrections.py`, `check_planning_fixes.py`). The folder is local
and not in the repository. Without it, these checks skip the parts that need it
and name the missing files.

`tests/action_route/fixtures/` : hand-written gold material: source artifacts,
gold source and query formulas, expected clause properties, and the small GK
inputs a check cannot express in Python. Written by hand and reviewed. Not
generated by a model, not copied out of a stored run.

## What does not belong here

**English benchmark lists.** The `tests/tests_*.py` files are lists of
`[id, input, expected]` triples that `test.py` and `runtests.py` execute
against a provider. Those runs cost money and call a model. Nothing in this
directory is such a list, and no runner discovers this directory. The
translation cohort for the WP16–WP20 pilot is a benchmark list and goes in
`tests/`, under its own name, not here. The planning test set
`tests/tests_planning.py` is such a list: `make_planning_tests.py` builds it
from `planning_rows.json` and the reviewed `planning_gold.json` here
(`tests/tests_planning_README.md`).

**Generated clause dumps.** The oracle is the reviewed gold, not the
compiler's own output. Per-run outputs live in the ignored results directory
`elogs/action_route_2026_09_10/`.

## Precedent

`tests/bridge_unit/` is the same kind of directory for the break-point
locator: hand-written fixtures, no LLM call, no stored run, no regeneration,
with the scoring benchmark kept elsewhere. Follow its record-schema style :
each fixture has a stable `id`, a one-line `purpose`, the input, the
reviewed expectation, and a note saying why the fixture exists.
