# planning test set

English problems about actions and plans for the action route of the nlpsolver pipeline
(`python3 solver/solve.py`; `-actions` forces the route). The texts state facts, permissions, rules and the results of
actions, and end with one question: a yes-no question, a question about a sequence of actions, a
wh-question, or a request for a plan. The rows are ordered from simple to complex, in eight sections.

## Files

- `tests_planning_basic.py` — the test: the same 126 cases as rows `[id, english_text, expected_answer,
  expected_actions]`. `expected_answer` is the answer text of the route, or a list of alternatives.
  `expected_actions` is the plan of that text as action terms with names
  (`[["move", "Greta", "Bergen", "Voss", "train"], ["change", "Greta", "cabin", "red", "unspecified"]]`),
  `[]` for the empty plan, or `None` when the text has no plan; with alternatives, one entry per
  alternative. A reachability question with a listed plan expects `"Yes. Plan: <sentence>."`.
- `tests_planning.py` — the detailed file: 126 cases, version 1.3. A Python list of complete rows
  `[id, english_text, expected_answer, reference]` with integer ids `1..126`, in `# == SECTION ==` blocks,
  with a table of contents at the top. The reference is a dict: the row's section and name, its origin
  and exposure, the reviewed gold translation (`stage1` and `stage2`, or the fixture's `formal` record),
  the listed plans as terms (`plans`), the reviewed expectation it was built from (`expect`), the reason
  code of a `Cannot answer` row, and the known limit of the present backend. The checker reads it; a
  reader needs it only to see why an answer is expected. 51 texts
  come from the v6 measurement of the action route, 49 from the reviewed gold fixtures, 9 were added
  in version 1.1 as partners of earlier rows (ids 101 to 109), and 17 in version 1.2 from the contrast
  run of prompt revision I (ids 110 to 126); the new rows stand in their sections. The v6 texts have
  been run through four models, and their failures have been read, so they are development material.
  The fixture texts had their first contact with a model in the run of 2026-09-30; prompt revision I
  was written after reading that run, so they are development material from then on. The contrast
  rows were run once (`tests_planning_contrasts.py`), and a controller repair was made after reading
  that run, so they are development material too. Rows 101 to 109 were first run through models in the
  full run of 2026-10-02.
- `tests_planning_dev.py` — the 11 texts that are prompt examples of the route's prompts, in the same
  form. They never enter a headline number.
- `tests_planning_contrasts.py` — the 17 contrast texts of prompt revision I, in the same form, as they
  were run on 2026-09-30 and 2026-10-02 (ids 1 to 17); the same texts are rows 110 to 126 of the set.

The files are generated by `tests/action_route/make_planning_tests.py` from
`tests/action_route/planning_rows.json`, the v6 cohort, the fixtures and
`tests/action_route/planning_gold.json` (the golds of the rows added in versions 1.1 and 1.2). A gold change
goes through `tests/action_route/fixtures/REVIEW.md` and a new build; the files are not edited by hand.

## Expected-answer semantics

| form | meaning |
|---|---|
| `True` / `False` / `None` (the basic file: `"Yes."`, `"No."`, `"Unknown."`) | yes / no / unknown: the text entails the statement, entails its negation, or neither |
| `"Yes. Plan: ..."`, `"Yes. No action is needed."` (the basic file only) | yes to a reachability question, with the listed plan |
| `"Plan: ..."` | a plan; this one is listed. The detailed checker also accepts any other valid plan; the basic checker does not |
| `"No action is needed."` | the goal holds at the start |
| `"No plan found."` | the text gives no way to the goal |
| a name, `"The key."` | the answer of a wh-question |
| `"Probably yes."` / `"Probably no."` | an answer that rests on a stated probability below 0.95 |
| `"Inconsistent."` | the text describes a contradictory state |
| `"Cannot answer: <reason>."` | the text is outside what the route models; the reason is for the reader |
| a list | any one of the alternatives |

The texts are read with an open world: what a text does not state is unknown. "Can Ann reach Tartu?"
without a stated way is `None`; "How can Ann get to Tartu?" is `"No plan found."`.

A text that is inside what the route models, but beyond the present prover, keeps the right answer
as its expected value. Its reference names the `known_limit`, and the row counts as wrong
until the prover answers it. In version 1.3: rows 29, 73 and 104 (a negative fact that must be kept
across an action) and row 64 (a four-step tower beyond the search).

A `Cannot answer` row lists a second answer when a careful reader has one clear answer, for example
`["No action is needed.", "Cannot answer: the route read one place as inside another, or one thing at
two places at once, which it does not model."]`. A plan given as such an alternative has no reference translation and is compared by
its text.

The word "Probably" is a display convention. The route puts it before an answer whose stated
uncertainty is below 0.95: "probably" and "with probability 0.8" give it, "with probability 0.99"
does not. The threshold 0.95 is no calibrated probability. The number, its parts and whether it is
experimental stay in the result record; the part that comes from the persistence of facts across
actions does not count. Row 87 ("with probability 0.99") expects `True`, and row 88 ("probably")
expects `"Probably yes."`.

## Conventions of the route

Four readings are conventions of the route: another reader could answer these texts differently. The
rows keep the route's answer, and each convention has a contrasting row.

| convention | rows | contrast |
|---|---|---|
| The last named snapshot is the default root: a question without a selection reads the latest snapshot. | 4 | 105 selects snapshot W0 explicitly |
| A supplied sequence is verified step by step: a denied step makes the answer No, a step without a permission makes it Unknown. | 26, 27 | 106 permits the step of row 26; 28 has a step without a permission |
| An effect grants no permission: "After Robo cooks the egg, ..." does not say that Robo can cook it. | 54 | 107 states the permission |
| Only a person moves by a public service without a stated rule. A robot needs a rule such as "Every robot can travel by bus". | 82, 83 | 108 has a person on the same route; 47 has the robot rule |

A state rule follows the convention of the profile
([the action prompt interface](../docs/encodings/action-prompts.md#scope-and-qualifications)): a
marker decides ("initially", "at the start" and "now" for a description of the start; "always", "at
all times", "at every state" and "whenever" for a standing rule); without a marker, a generic
dependency between states is a standing rule and a description of the scene is a description of the
start. Row 32 has no marker, and rows 101 and 102 have both markers.

## The answer text of the route

The action route answers in these forms ([answer text](../docs/architecture/action-answers.md#answer-text)):
`Plan: <sentence>.`, `Yes. Plan: <sentence>.` for "Can X eventually ...", `No action is needed.`,
`No plan found.`, `Yes.`, `No.`, `Unknown.`, a name, `Inconsistent: <facts in English>.`,
`Cannot answer: <sentence>. [<reason codes>; <units>]` for a text the route does not model, and
`Error: ...` for a failed run. An answer with a stated probability below 0.95 reads `Probably yes.`,
`Probably no.`, `Probably yes. Plan: <sentence>.` or `Probable plan: <sentence>.`. A `Cannot answer`
sentence says what the route read in the text and that it does not model it, for example "the route
read a rule as a restriction of a means, an actor or a tool, which it does not model".

## Grading

The test is run on the basic file, `tests_planning_basic.py`. Its checker, `solver/planning_check.py`,
compares the route's answer with the row's expected text, with its expected action list, or with both
(`runtests.py -answer-check text|actions|both`; the default is `text`). It never reads the detailed
file.

| mode | what decides |
|---|---|
| `text` | the answer text against the expected text |
| `actions` | the route's plan (`plan_named` of its result) against the expected action list, where the alternative has one; the text where it has none |
| `both` | the text, and the plan where the alternative has an action list |

The text comparison reads each text into a kind and its parts. It accepts differences that come from
the translation rather than from the answer. It is a heuristic and can be wrong:

| rule | what counts as the same |
|---|---|
| T1 | case, spacing, the final period and the articles "the" and "an"; "a" before a noun ("a cake"), but not a name ("block a") |
| T2 | Yes, No, Unknown, Contested: the kind and the word "Probably" must agree; `True` and `False` are Yes and No |
| T3 | a plan after Yes ("Yes. Plan: ...") is extra when the expected text is a bare "Yes."; when the expected text has a plan, the plans are compared |
| T4 | a plan: the same steps in the same order and the same qualifier ("Plan", "Probable plan"); a thing may have an extra word before its noun ("the robot hand" for "the hand", "the flour cake" for "a cake"); "in" equals "with" before the tool at the end of a change step |
| T5 | a wh-answer: the same names in any order |
| T6 | `Cannot answer` matches `Cannot answer`, whatever its sentence and its bracket of reason codes; on a `Cannot answer` alternative, `Unknown.` and `No plan found.` count as not answered (correct) |
| T7 | `Inconsistent` with or without its facts; `No action is needed.` with or without `Yes.`; `No plan found.` for an expected `Unknown.` |
| T8 | `Error: ...` is never correct |

The action comparison:

| rule | what counts as the same |
|---|---|
| A1 | the same actions with the same arguments, in order; names by T1, with the extra word of T4 |
| A2 | `[]` is the empty plan; an answer without a plan matches no action list |
| A3 | a change step whose result value alone differs, when the route's source verb of that step is the step's verb in the expected text: "fried" for "cooked" when both say "fries" |

Grades: `match` and `not_answered` are correct; `mismatch`, `no_answer` (`Cannot answer` where an
answer was expected) and `error` are wrong. With a list of alternatives the best grade counts, and the
detail names the alternative.

Neither mode validates a plan that differs from the listed ones: a longer plan, or one with a repeated
step, is wrong even when it reaches the goal.

The detailed file has a checker of its own, `solver/action_check.py` (version 2). It grades plans by
their terms and validates other plans by a replay on the gold translation. `make_planning_tests.py` and
`tests/action_route/check_planning_tests.py` use it to check the detailed file. The runner does not use
it.

## Running

```bash
python3 runtests.py tests/tests_planning_basic.py -actions -llms gemini -limit 5
python3 runtests.py tests/tests_planning_basic.py -actions -answer-check both -llms gemini -limit 5
python3 runtests.py tests/tests_planning_basic.py -llms gemini -limit 5
```

With `-actions` every text goes to the action route, which measures the route itself. Without it, each
text is routed by the classifier as in a one-example call
([experimental options](../docs/reference/experimental-options.md#the-action-route)), which measures the routing too: a text the classifier finds unclear goes to the ordinary
pipeline. On a planning test file, `runtests.py` grades each answer with `planning_check.grade_row` in the chosen mode, and
refuses a file whose rows hold a gold translation in place of an action list (the detailed file). It
runs the providers one after another, so GK runs serially. Each case file holds `correctness`, `grade`,
`answer_check` (the detail, with the mode) and the checker's `scoring_policy`. The summary's
`planning` block counts the answers correct, the rows correctly not answered, the wrong rows and the
errors.

## Sections

`tests_planning.py` begins with a table of contents. In brief: states and snapshot questions;
permissions; effects and supplied sequences; plans of one step, and no plan; plans of several steps;
step bounds and empty plans; uncertainty; texts outside the profile, and contradictory states.
