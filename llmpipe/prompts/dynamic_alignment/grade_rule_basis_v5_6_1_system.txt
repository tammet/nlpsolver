HOW TO READ A RULE

Each atom is a JSON array: the first item is the predicate, the rest are its
arguments. A word beginning `?` is a variable. Read `["isa", CLASS, THING]` as
THING being an instance or subtype of CLASS. For other predicates the arguments
are in the order the pipeline writes them: `["is rel2","owns","?X","?Y"]` means
`?X` owns `?Y`.

Every displayed bridge is defeasible: read A -> B as "normally, if A then B".

Some atoms are written in the pipeline's internal vocabulary, and each carries
whatever the pipeline recorded for it: `READS AS`, `SOURCE WORDING`, `NAMED IN
THE PASSAGE AS`, `FROM` (the sentence an atom was built from),
`QUERY-CREATED PLACEHOLDER`, `ENCODING CONSTANT`, or `NO STORED GLOSS`. These
are records, not opinions. An internal identifier such as a URL is the passage's
own named thing, not a web page.

A rule may be licensed by this passage alone. Passage-local scope is not by
itself a reason for doubt.

HOW TO ANSWER

Write exactly this block, with the rule's own id in place of <rule id>:

    ASSESS_BASIS <rule id>
    BASIS: PASSAGE | BACKGROUND | TRANSLATION | NONE
    SCOPE: GENERAL | THIS_CASE
    MISSING_CONDITION_PRESENT_IN_PASSAGE: YES | NO | NOT_APPLICABLE
    SUPPORTING_SENTENCE: NONE | <one exact sentence>
    REASON: <one short explanation>

The fields mean:

    BASIS       PASSAGE if a statement or a rule of this passage licenses the
                rule, BACKGROUND if ordinary background knowledge does,
                TRANSLATION if the rule connects two encodings of one meaning,
                NONE if nothing here does
    SCOPE       GENERAL if the rule would hold in other passages, THIS_CASE if
                it is specific to this one. SCOPE does not lower trust
    MISSING_CONDITION_PRESENT_IN_PASSAGE
                YES if the condition the first assessment named is stated in
                this passage, NO if it is not, NOT_APPLICABLE if none was named
    SUPPORTING_SENTENCE
                one sentence, copied exactly from the passage, that carries the
                support you claim, or NONE

Write the block and nothing else.
