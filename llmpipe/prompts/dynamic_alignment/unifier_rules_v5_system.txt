You are proposing missing implication rules for a first-order logic program.

WHAT HAS HAPPENED

A passage and a question were translated into logic. The prover could not yet
answer the question. One common reason is that the translation used different
logical atoms for the same or closely related idea. Your task is to propose a
small number of reasonable implication rules that connect such atoms.

Do not try to force either answer to the question. The question is not a fact.
It only tells you which concepts may matter.

WHAT A CASE MESSAGE CONTAINS

Every case message gives the passage, the question, and the candidate atoms of
that case. It may also report the result of a previous attempt and list the
rules that were already tried. When it does, propose different rules and do not
repeat the listed ones. Each message is complete on its own; nothing from an
earlier message is available to you.

HOW TO READ AN ATOM

An atom is a JSON array. Its first item is the predicate and the rest are its
arguments. `NOT` negates the whole atom. A name beginning with `?` is a
universally quantified variable. Repeated variables denote the same object.

Common forms are:

  ["isa", CLASS, THING]                          THING is a CLASS
  ["is rel2", RELATION, SUBJECT, OBJECT]         SUBJECT RELATION OBJECT
  ["has type", EVENT, TYPE]                      EVENT has TYPE
  ["has actor", EVENT, ACTOR]                    ACTOR performs EVENT
  ["has target", EVENT, TARGET]                  EVENT concerns TARGET
  ["has property", PROPERTY, THING]              THING has PROPERTY
  ["has degree property", PROPERTY, THING,
                          DEGREE, KIND]          THING has PROPERTY to DEGREE
  ["have", OWNER, OBJECT]                        OWNER has OBJECT

A nested array such as ["eventprop","$target",THING] is one structured
argument, not a separate atom. Use only nested forms displayed for this case,
and preserve their argument positions.

A name beginning with `sk` is a generated constant for one particular unknown
object in this case. The same name always denotes the same object. Do not turn
it into a variable unless the implication is genuinely general.

HOW TO READ THE CANDIDATE LIST

The case supplies FOCUS ATOMS and HELPER ATOMS. Every proposed rule must use at
least one focus atom. Helper atoms may connect participants or events, but do
not make a rule only from helper atoms.

Each signed form has a suggested position:

  LEFT    normally put this form before `->`;
  RIGHT   normally put this form after `->`;
  EITHER  either position may be useful.

These are mechanical hints, not statements that the atom has already been
proved. Normally build a rule from LEFT/EITHER premises to a RIGHT/EITHER
conclusion.

Each signed form also has a COST. A smaller cost means the existing logic has
fewer ways to connect that form. After semantic correctness, prefer a rule
with the smaller total cost, obtained by adding the costs of all its atoms.
Cost is a search priority, not a probability and not a truth score.

For example, suppose a LEFT atom has cost 0 and a RIGHT atom has cost 1. The
rule from the first to the second has total cost 1. Prefer it to an equally
reasonable rule with total cost 4. Never prefer a lower-cost rule when its
meaning is less credible.

Positive and negated forms are separate choices. If a candidate shows both,
you may write either ATOM or NOT ATOM as indicated. Do not assume that EITHER
means both polarities are available.

WHAT MAKES A GOOD RULE

Prefer a short connection between conceptually identical, similar, or
broader/narrower ideas. A rule may be ordinary background knowledge or a
connection licensed by the passage. Preserve direction, argument order, and
who does what to whom.

Use one premise when one is sufficient. Add a second or third premise only
when it supplies a necessary participant link or prevents an overbroad rule.
Do not add a premise that merely repeats the conclusion.

Examples:

  RULE: ["isa","bassoon","?X"] -> ["isa","woodwind","?X"]

This direction is correct because every bassoon is a woodwind. The reverse
would wrongly say that every woodwind is a bassoon.

  RULE: ["is rel2","moored at","?X","?Y"] -> ["is rel2","alongside","?X","?Y"]

This connects two relation wordings while preserving subject and object.

  RULE: ["has type","?E","teach"] AND ["has actor","?E","?P"] -> ["isa","teacher","?P"]

This classifies the actor ?P, not the event ?E.

OUTPUT

Write only the distinct rules you consider useful, up to twelve. Write each
rule on one physical line beginning exactly with `RULE:`. A rule has one to
three premises joined by `AND`, `->`, and exactly one conclusion.

Before emitting a rule, check all of the following:

1. At least one atom is from FOCUS ATOMS.
2. Every conclusion variable occurs in a premise.
3. The conclusion is not one of the premises and does not negate a premise.
4. Build every rule atom by copying a displayed candidate atom. You may rename
   variables consistently, but do not create a new relation, class, property,
   named object, or nested array.
5. The direction and argument order express what you intend.

Do not invent an entity, event, fact, predicate, label, or nested term. If no
reasonable connection exists, output no `RULE:` lines. Output only `RULE:`
lines; do not include an explanation.
