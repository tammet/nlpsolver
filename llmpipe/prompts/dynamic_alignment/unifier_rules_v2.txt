A logic program needs a few missing implication rules. You are given candidate
atoms from that program. Propose rules that connect atoms which express the
same concept, a broader or narrower concept, or a closely related relation.

HOW TO READ THE CANDIDATES

Each atom is a JSON array. The first item is its predicate; the remaining items
are its arguments. `NOT` means negation.

    ["isa","bassoon","?X"]
    NOT ["isa","silent","?X"]
    ["is rel2","plays in","?X","?Y"]

For `isa`, the order is always:

    ["isa", CLASS, THING]

A variable begins with `?`. Every variable is universally quantified: `?X`
means every object that satisfies the rule's premises, not one convenient
object from this passage. The same variable in two places means the same
object.

Each candidate says how it can help:

  * PREMISE: the current logic can potentially supply this atom, so it is a
    natural choice on the left of `->`.
  * CONSEQUENCE: the current logic has a place that needs this atom, so it is a
    natural choice on the right of `->`.
  * BOTH: it can be useful in either position.

These roles are guidance, not an absolute prohibition. A short chain of two
new rules may use the consequence of the first rule as a premise of the second.

Every candidate also has a PRIORITY COST. A smaller number means the atom has
fewer existing ways to participate in a proof, with an extra preference for
atoms connected to the question. Prefer rules whose atoms have a small total
priority cost, but semantic correctness is more important than the number.

The MAIN list contains the most relevant candidates. Use it first. The
SECONDARY list contains additional atoms from the same logic program. Use a
secondary atom when no sensible rule can be made from the main list alone.

RULE DIRECTION AND MEANING

Write only implications that are generally true or reasonable normal-case
connections.

A narrower class implies a broader class:

    GOOD: RULE: ["isa","bassoon","?X"] -> ["isa","woodwind","?X"]
    BAD:  RULE: ["isa","woodwind","?X"] -> ["isa","bassoon","?X"]

The bad direction says that every woodwind is a bassoon. Do not write both
directions unless both really hold.

Do not infer a missing relation merely from a noun. For example, this is bad
without another premise connecting employees to chemistry:

    BAD: RULE: ["isa","employee","?X"] -> ["isa","chemist","?X"]

Do not silently change who does what to whom. Argument order matters:

    ["is rel2","owns","?X","?Y"]

means that `?X` owns `?Y`, not the reverse.

OUTPUT FORMAT

Write zero or more rules, at most twelve. Each rule must be on one physical
line and begin exactly with `RULE:`.

    RULE: ["isa","bassoon","?X"] -> ["isa","woodwind","?X"]
    RULE: ["is rel2","plays in","?X","?Y"] AND ["isa","orchestra","?Y"] -> ["isa","musician","?X"]
    RULE: ["isa","soloist","?X"] -> NOT ["isa","conductor","?X"]

Rules may have one to three premises joined by `AND` and exactly one
consequence. Use only predicates, labels, constants, and nested term shapes
shown in the candidate lists. A consequence variable must occur in a premise.
You may replace a named example with a variable only when the implication is a
genuine general rule; the program will mark that generalization for later
checking.

Only `RULE:` lines are executed. Explanatory prose is kept for audit but is not
parsed. If no implication is sensible, write no `RULE:` lines.

Do not solve the question and invent rules that force an answer. Your task is
only to propose independently reasonable connections between the displayed
atoms.
