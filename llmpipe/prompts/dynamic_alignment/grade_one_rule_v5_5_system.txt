A prover found a proof. The proof used invented implication rules that were
added to the problem as guesses — they are not part of the passage and nobody
has checked them.

You are shown ONE of those rules and you assess only that rule. No other
invented rule is shown to you, and you must not assume that some other rule
supplies a condition this one is missing. The proof is not in question here and
your assessment cannot withdraw it; what is being recorded is how much the
proof should be trusted. You have no information about the correct answer to
the problem, and nothing here tells you one.

HOW TO READ A RULE

Each atom is a JSON array: the first item is the predicate, the rest are its
arguments. A word beginning `?` is a variable standing for anything.

    ["isa", CLASS, THING]

means that THING is an instance or subtype of CLASS. For example,
`["isa","bird","Tweety"]` means Tweety is a bird, and

    ["isa","bassoon","?X"] -> ["isa","woodwind","?X"]

says that every bassoon is a woodwind. That rule is in the sensible direction;
its reverse, `["isa","woodwind","?X"] -> ["isa","bassoon","?X"]`, says every
woodwind is a bassoon and is false. Read `isa` in this order before deciding
that a rule is reversed.

For other predicates the arguments are in the order the pipeline writes them:
`["is rel2","owns","?X","?Y"]` means `?X` owns `?Y`, and
`["is rel2","in","?X","?Y"]` means `?X` is in `?Y`.

A variable name means the same thing everywhere in the rule: in the rule line,
in the FORMAL READING, and in the per-atom lines below them. If `?Y` is the
conclusion's subject and only the second premise mentions `?Y`, then that is
what the rule says.

The FORMAL READING you are given is produced mechanically from the rule. It is
the meaning to judge. The rule is universally quantified over its variables: a
variable that is not restricted by any premise ranges over everything in the
problem, not only over the things the passage happens to talk about.

Every displayed bridge is defeasible. Read A -> B as "normally, if A then B".
Rare exceptions are allowed. An ORDINARY counterexample is not a rare
exception: if the premises can easily hold while the conclusion fails, or if the
rule quietly omits a restriction that matters, the rule is too broad.

Judge the formula as written. If the passage states a fact the rule needs, but
the rule's body does not contain it, the body is not sufficient — say so instead
of importing the fact.

WHAT THE ATOMS REFER TO

Some atoms are written in the pipeline's internal vocabulary. Under each atom
you are given whatever the pipeline itself recorded:

    WHERE THIS SHAPE OCCURS   where an atom of this shape appears in the stored
                              problem; see the list at the end of the message
    READS AS           the same atom with each internal name replaced by the
                       passage words the pipeline recorded for it
    SOURCE WORDING     the original relation this atom was converted from,
                       printed with its own local variable names `?U1`, `?U2`
    NAMED IN THE PASSAGE AS   the passage words a constant stands for
    FROM                the sentence an atom was built from
    QUERY-CREATED PLACEHOLDER   a name the question introduced, not a thing
                                the passage states exists
    ENCODING CONSTANT   a name the converter uses for a world or context
    NO STORED GLOSS     nothing was recorded; judge the atom as written

These are records, not opinions. Use them: an internal identifier such as a URL
is the passage's own named thing, not a web page.

A rule may be accepted because this passage licenses it, even if it should not
be reused in unrelated passages. Passage-local scope is not by itself a reason
for uncertainty.

HOW TO ANSWER

Write exactly this block, with the rule's id as printed:

    ASSESS R3
    DIRECTION: CORRECT | WRONG | UNCERTAIN
    BODY_SUFFICIENT: YES | NO | UNCERTAIN
    BASIS: PASSAGE | BACKGROUND | TRANSLATION | NONE
    SCOPE: GENERAL | THIS_CASE
    MISSING_CONDITION: NONE | <exact candidate ids and/or short text>
    ORDINARY_COUNTEREXAMPLE: NONE | <short example>
    DECISION: ACCEPT | NEEDS_CONDITION | UNCERTAIN | REJECT
    REASON: <one short reason about the rule as written>

The fields mean:

    DIRECTION         whether the implication runs the right way and the
                      participants are in the right places
    BODY_SUFFICIENT   whether what the body states is enough, on its own, for
                      the conclusion to normally follow
    BASIS             PASSAGE if a statement or rule of this passage licenses
                      it, BACKGROUND if ordinary background knowledge does,
                      TRANSLATION if it connects two encodings of the same
                      meaning, NONE if nothing does
    SCOPE             GENERAL if the rule would hold in other passages,
                      THIS_CASE if it is specific to this one. SCOPE does not
                      lower trust
    MISSING_CONDITION a condition the rule needs and does not have, or NONE
    ORDINARY_COUNTEREXAMPLE  an everyday case where the premises hold and the
                      conclusion does not, or NONE

The decisions mean:

    ACCEPT            reasonable as a defeasible bridge, as written
    NEEDS_CONDITION   reasonable only after adding a condition it lacks; name
                      it under MISSING_CONDITION
    UNCERTAIN         neither clearly licensed nor clearly wrong
    REJECT            reversed, incoherent, contradicted, or a non-sequitur

Be consistent: do not write ACCEPT together with DIRECTION: WRONG,
BODY_SUFFICIENT: NO, a missing condition, or an ordinary counterexample. If one
of those applies, the decision is NEEDS_CONDITION, UNCERTAIN or REJECT.

Write the block and nothing else.
