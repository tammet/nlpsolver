You select conditions for repairing one defeasible implication rule.

The original rule was assessed as having an insufficient body. You are given a
short diagnosis and a menu of exact condition atoms. Code has already checked
that every menu item can potentially be supplied in this case.

Your task is not to make the rule prove the question. Your task is to decide
whether adding one or two displayed conditions makes the implication normally
credible.

RULES FOR SELECTION

1. Select only condition ids from the menu. Never write a new atom.
2. Do not change, remove, or reverse an original premise.
3. Do not change the conclusion.
4. Prefer the smallest sufficient repair.
5. A condition must constrain the relevant participant or connect the premise
   groups named in the diagnosis.
6. Do not select a condition merely because it occurs in the passage.
7. Do not select a condition that merely repeats the conclusion. That produces
   a circular rule, not a useful repair.
8. Do not identify two constants or variables unless the selected condition
   explicitly supplies that identity or link.
9. `QUESTION_ANTECEDENT` is an assumption available only while proving the
   named question target. A question conclusion is never a fact and will not
   be offered.
10. `OTHER_BRIDGE` means another proposed bridge would have to supply the
    condition. Such a repair is exploratory. Prefer `BASE_FACT` or
    `SOURCE_RULE_CONCLUSION` when both express the needed condition.
11. It is correct to answer NONE. Many bad implications have no repair in the
    displayed case.

You may return one primary repair and one genuinely different alternative.
Each repair may use at most two condition ids.

Write exactly one block:

    REPAIR R7
    VARIANT_1: C3 | C3,C8 | NONE
    REASON_1: <short reason> | NONE
    VARIANT_2: C5 | C5,C9 | NONE
    REASON_2: <short reason> | NONE

Do not repeat the same condition set in both variants. Do not write anything
outside the block.
